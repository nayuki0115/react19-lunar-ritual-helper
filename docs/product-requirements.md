# Lunar Ritual Helper 產品需求規格

## 1. 文件目的

本文件是 Lunar Ritual Helper 新版重構的產品需求與領域規則來源，用於功能實作、程式審查、單元測試與里程碑驗收。

本文件描述的是目標規格，不代表目前 production 已完成所有功能。若現有程式行為與本文件不同，後續重構應以本文件為準。

## 2. 產品定位

Lunar Ritual Helper 是純前端、手機優先的工具型 Web App，協助使用者整理民間疏文常見欄位。所有換算均在使用者瀏覽器內完成，不使用後端、帳號系統、資料庫、網站分析、廣告追蹤或外部錯誤追蹤。

### 2.1 目標使用情境

- 民間疏文填寫
- 拜拜與祭祀資料整理
- 補運、祭改、安太歲等需要出生農曆資料的場合
- 核對出生農曆、生肖、時辰與虛歲

### 2.2 非目標

- 不進行紫微斗數或其他命理命宮推算。
- 不產生完整疏文內容。
- 不驗證宮廟、法師或特定疏文格式的個別規範。
- 第一階段不支援直接輸入閏月農曆生日。
- 第一階段不加入後端同步、帳號或雲端儲存。

## 3. 名詞與疏文欄位

主要結果區依下列順序顯示：

| 順序 | 疏文欄位 | 系統顯示 | 說明 |
| --- | --- | --- | --- |
| 1 | 天運 | 今日干支年及農曆月日 | 實際疏文常要求填寫完整今日農曆日期 |
| 2 | 歲次 | 今日干支年及農曆月日 | 本義為當年干支年；實際疏文常連同今日農曆月日填寫 |
| 3 | 命宮 | 出生干支年、農曆月日及時辰 | 與「生辰」、「本命」填寫相同內容 |
| 4 | 生辰 | 出生干支年、農曆月日及時辰 | 未知出生時間時使用「吉時」 |
| 5 | 本命 | 出生干支年、農曆月日及時辰 | 與「生辰」、「命宮」填寫相同內容 |
| 6 | 歲數 | 目前虛歲 | 依目前農曆年度計算 |
| 7 | 手印 | 左手印或右手印 | 男左女右，一般參考 |

出生生肖與流年生肖不列入主要疏文欄位，可顯示於參考資訊或詳細資訊。

「天運」與「歲次」是不同欄位。「歲次」本義是當年的干支年；但實際疏文中的「天運」欄位或「歲次」欄位，常都要求填寫當年農曆干支年份及當天農曆月日。為避免重複，系統提供一組可供兩種欄位使用的完整內容。例如：

- 天運／歲次（疏文填寫內容）：`丙午年 六月廿二`

「生辰」、「命宮」與「本命」是不同疏文可能採用的欄位名稱，在本產品中都填寫相同的出生農曆資料：出生干支年、農曆月日及時辰。結果區標題需明確標示「農曆出生資料」，並合併顯示一次，避免資訊重複。例如：

- 生辰／命宮／本命：`壬申年 十二月初八 丑時`

此處「命宮」是疏文欄位名稱，不進行紫微斗數或其他命理命宮推算；「本命」也不再直接等同出生生肖。生肖另列為參考資訊。

## 4. 時區與兩套日期規則

系統時區固定為 `Asia/Taipei`。

### 4.1 出生資料時間軸

出生資料永遠使用民用日期規則，於 00:00 換日，不受換日模式 `dm` 影響：

- 出生國曆日期
- 出生農曆生日
- 出生農曆年
- 出生生肖
- 出生生辰

出生農曆資料直接由出生當天的國曆日期換算。23:00–23:59 出生仍屬於該民用日期，不因子時而推進至隔日。

範例：

- 2025-01-28 23:30 出生：
  - 國曆生日為 2025-01-28。
  - 農曆生日仍為除夕。
  - 生肖屬上一農曆年度生肖。
- 2025-01-29 00:30 出生：
  - 國曆生日為 2025-01-29。
  - 農曆生日為正月初一。
  - 生肖屬新農曆年度生肖。

### 4.2 目前日期時間軸

目前日期相關資訊依使用者選擇的換日模式判定：

| 模式 | 參數值 | 換日時間 |
| --- | --- | --- |
| 民俗模式 | `folk` | 23:00 |
| 民用模式 | `civil` | 00:00 |

預設模式為 `folk`。

`dm` 影響：

- 今日農曆日期
- 今日天運／歲次填寫內容
- 今日生肖／流年生肖
- 目前虛歲
- 其他依今日農曆日期計算的資訊

`dm` 不影響任何出生資料。

在農曆除夕的年度邊界：

- `folk`：23:00 起視為正月初一，今日天運／歲次填寫內容、流年生肖及虛歲同步更新。
- `civil`：00:00 起才進入正月初一並更新。

### 4.3 「今天」的驗證定義

判斷生日是否晚於今天時，今天一律使用 `Asia/Taipei` 的民用日期，於 00:00 換日，不使用 `dm`。

## 5. 虛歲規則

虛歲依農曆年度計算，不依國曆生日或生日是否已過計算：

```text
目前虛歲 = 目前農曆年 - 出生農曆年 + 1
```

- 出生時即為一歲。
- 每進入一個新農曆年度增加一歲。
- 國曆年初但農曆新年前出生者，其出生農曆年仍屬上一年度，因此相較周歲可能呈現「實歲 +2」。
- 不得在農曆年差公式完成後再額外加一，否則會重複計算。
- 目前農曆年依 `dm` 判定，因此在除夕 23:00–23:59，`folk` 與 `civil` 可能得到不同虛歲。

## 6. 出生時間與時辰

### 6.1 輸入模式

出生時間支援：

- 不知道
- 已知時辰
- 已知幾點幾分

條件式驗證：

- 選擇已知時辰時，時辰必填。
- 選擇精確時間時，有效時間必填。
- 選擇不知道時可以產生結果，生辰使用「吉時」。
- 已知時辰的子時選項分為「子時（不確定早晚）」、「早子時」與「夜子時」，讓使用者依已知程度選擇。

### 6.2 時辰邊界

每個時間點只能對應一個時辰：

| 時辰 | 範圍 |
| --- | --- |
| 早子時 | 00:00–00:59 |
| 丑時 | 01:00–02:59 |
| 寅時 | 03:00–04:59 |
| 卯時 | 05:00–06:59 |
| 辰時 | 07:00–08:59 |
| 巳時 | 09:00–10:59 |
| 午時 | 11:00–12:59 |
| 未時 | 13:00–14:59 |
| 申時 | 15:00–16:59 |
| 酉時 | 17:00–18:59 |
| 戌時 | 19:00–20:59 |
| 亥時 | 21:00–22:59 |
| 夜子時 | 23:00–23:59 |

精確時間的主要結果只顯示換算後時辰，不預設顯示原始時間。原始時間可顯示於詳細資訊。

生辰／命宮／本命格式：

- 已知時辰：`壬申年 十二月初八 丑時`
- 未知時辰：`壬申年 十二月初八 吉時`
- 精確時間落在 23 點：顯示「夜子時」。
- 精確時間落在 00 點：顯示「早子時」。

出生時辰不會改變出生日期。

## 7. 農曆文字格式

主要結果採傳統疏文格式：

- 日期：
  - 初一至初十
  - 十一至十九
  - 二十
  - 廿一至廿九
  - 三十
- 月份：
  - 使用「正月」，不使用「一月」。
  - 使用「十一月」與「十二月」。
- 干支年：例如「壬申年」、「乙巳年」。
- 生肖：例如「屬猴」、「屬蛇」。

國曆自動換算遇到閏月時，必須保留「閏」字，例如：

- 生辰／命宮／本命：`癸卯年 閏二月初八 午時`

白話日期格式不在主要結果顯示；未來可作為詳細資訊或設定功能。

## 8. 出生資料輸入模式

### 8.1 國曆自動換算

必填資料：

- 性別
- 國曆出生日期
- 出生時間模式
- 時辰或精確時間（依模式條件式必填）

系統負責換算：

- 出生農曆年
- 出生農曆生日
- 出生干支年
- 出生生肖
- 生辰

出生國曆日期：

- 不得晚於 `Asia/Taipei` 民用日期的今天。
- UI 不設定固定最早年份。
- 凡 `lunar-javascript` 可成功轉換的日期皆可使用。
- 超出支援範圍時顯示「此日期不在支援範圍內」。

### 8.2 已知農曆直接填寫

必填資料：

- 性別
- 農曆出生年（使用西元年份，例如 `1992`）
- 農曆月
- 農曆日
- 出生時間模式
- 時辰或精確時間（依模式條件式必填）

不要求國曆生日或手動輸入生肖。系統依農曆出生年取得干支年與生肖，但不重新換算使用者提供的農曆月日。

介面需明確提示使用者填寫西元年份，系統會自動換算干支與生肖。

第一階段只進行基本驗證：

- 農曆出生年必須是有效整數，且能由 `lunar-javascript` 產生干支與生肖。
- 月份限制為 1–12。
- 日期限制為 1–30。
- 出生農曆年不得晚於依 `dm` 判定的目前農曆年。
- 不驗證該農曆月實際有 29 或 30 天。
- 不支援或驗證閏月。

介面必須顯示：

> 目前僅驗證基本格式，不驗證農曆日期是否實際存在；請確認輸入的農曆生日正確。閏月生日暫不支援。

結果必須標示：

> 此出生農曆資料由使用者自行提供。

### 8.3 模式切換與草稿

- 國曆與農曆模式各自保留輸入草稿。
- 提交、驗證、結果與分享只使用目前模式資料。
- 經使用者同意後，LocalStorage 可保存兩組草稿及最後選擇的模式。
- 清除資料會一次清除兩組草稿。
- 分享連結不得包含非目前模式的草稿。

## 9. 性別與手印

- 性別必填。
- 第一階段只提供「男」與「女」。
- 男：左手印。
- 女：右手印。
- 未選性別時不可產生完整結果，提示「請選擇性別」。

介面需說明手印規則僅供一般參考；若宮廟、法師或疏文已有指定，應以實際規定為準。

## 10. 表單驗證

### 10.1 一般表單

- 性別未選：禁止產生結果並顯示對應提示。
- 生日未填、格式錯誤、日期不存在或晚於今天：禁止產生結果並顯示具體原因。
- 日期超出農曆套件支援範圍：禁止產生結果。
- 已知時辰但未選時辰：禁止產生結果。
- 已知精確時間但時間缺少或無效：禁止產生結果。
- 不知道出生時間：允許產生結果，顯示「吉時」。

### 10.2 分享連結

採「嚴格驗證、容錯處理」：

- 必要資料缺少或錯誤：整組分享資料不載入。
- 可選資料缺少：使用預設值。
- 條件式資料在對應模式中視為必要資料。
- 無效資料不得讓頁面崩潰或產生部分錯誤結果。

## 11. 頁面與互動流程

### 11.1 表單

採單頁分區與漸進揭露，不使用多步驟 Stepper：

1. 選擇國曆自動換算或已知農曆直接填寫。
2. 顯示目前模式的日期欄位。
3. 選擇出生時間模式。
4. 展開目前時間模式所需欄位。
5. 在次要區域提供換日模式及記住選項。
6. 驗證後選擇「產生疏文資料」。

手機採單欄垂直排列；桌機可使用雙欄。

### 11.2 結果

- 天運／歲次填寫內容及流年生肖等非個人資訊進站即顯示。
- 個人出生結果只在有效資料成功產生後顯示。
- 產生前不顯示大量 `--`。
- 換算是同步作業，不加入固定 Loading 或人為延遲。
- 結果顯示後可在行動裝置自動捲動至結果區。
- 自動捲動需尊重 `prefers-reduced-motion`。

### 11.3 詳細資訊

預設收合，包含：

- 原始出生時間及時間輸入模式
- 出生國曆日期（若適用）
- 出生農曆生日、生辰／命宮／本命及參考生肖
- 天運／歲次填寫內容、流年生肖及虛歲
- 目前換日模式
- 出生資料與目前資料各自使用的判定規則
- 虛歲計算式

詳細資訊展開狀態只有在使用者啟用「記住設定」時才保存。

### 11.4 自動換日更新

- `folk` 排程至下一個台北時間 23:00。
- `civil` 排程至下一個台北時間 00:00。
- 到達換日時間後重新計算所有目前日期相關資訊。
- 不使用每分鐘輪詢。
- 切換 `dm` 時取消舊排程並建立新排程。
- 瀏覽器恢復 focus 或頁面由隱藏轉為可見時立即重新檢查。
- 不要求使用者重新輸入或重新產生出生資料。

## 12. LocalStorage 與隱私

### 12.1 原則

- 個人資料及 UI 設定皆採 Opt-in，預設關閉。
- 不因一般輸入或產生結果而自動保存。
- 個人資料與 UI 設定使用不同、帶版本的 storage key。
- 所有資料只在本機處理，主動建立分享連結時除外。

### 12.2 記住我的資料

保存：

- 性別
- 國曆與農曆兩種模式草稿
- 出生時間及時間模式
- 最後選擇的出生資料模式

規則：

- 預設關閉。
- 開啟後才建立個人資料 storage。
- 關閉時立即刪除既有個人資料 storage。
- 下次開啟網站時自動還原。

### 12.3 記住設定

保存：

- 換日模式
- 詳細資訊展開狀態
- 分享提醒偏好
- 未來新增的純 UI 偏好

規則：

- 預設關閉。
- 開啟後才建立設定 storage。
- 關閉時立即刪除既有設定及分享提醒偏好。
- 未保存設定時，每次新工作階段使用 `folk` 並收合詳細資訊。

### 12.4 優先順序

資料初始化優先順序：

```text
有效分享 URL > 已經 Opt-in 保存的 LocalStorage > 系統預設
```

分享 URL 的 `dm` 只影響本次頁面，不覆蓋本機偏好。

### 12.5 清除資料

- 清空兩種出生模式的所有草稿。
- 清除目前個人結果。
- 刪除新版個人資料 storage。
- 移除分享 URL query parameters，使用 `history.replaceState`，不新增歷史紀錄。
- 保留設定 storage 與 UI 偏好。
- 天運／歲次填寫內容等非個人資訊持續顯示。

### 12.6 重設設定

- 刪除設定 storage。
- 關閉「記住設定」。
- 詳細資訊恢復收合。
- 分享恢復每次顯示隱私提醒。
- 一般頁面換日模式恢復 `folk`。
- 不清除個人資料。
- 有效分享連結存在時仍以 URL 的 `dm` 為準；離開分享狀態後才使用 `folk`。

### 12.7 舊版資料清理

- 新版首次載入時檢查舊 key `lunar-ritual-form`。
- 若存在則直接刪除。
- 不讀取、不顯示、不移轉至新版。
- 不因此建立任何新版 storage。
- 這是一次性升級清理。

## 13. 分享連結

### 13.1 隱私原則

- 一般產生結果不將個人資料寫入 URL。
- 只有使用者主動選擇分享或複製連結時才建立分享 URL。
- 分享 URL 包含性別、出生日期或農曆生日、出生時間及換日模式。
- 建立前需依提醒偏好顯示個人資料告知。
- 分享資料不自動寫入或覆蓋 LocalStorage。

### 13.2 Schema v1

| 參數 | 值 | 說明 |
| --- | --- | --- |
| `v` | `1` | Schema 版本 |
| `bm` | `s`／`l` | 國曆自動換算／農曆直接填寫 |
| `g` | `m`／`f` | 性別 |
| `b` | `YYYY-MM-DD` | `bm=s` 時的國曆生日 |
| `ly` | 整數 | `bm=l` 時的農曆出生年 |
| `lm` | 1–12 | `bm=l` 時的農曆月 |
| `ld` | 1–30 | `bm=l` 時的農曆日 |
| `tm` | `u`／`br`／`ex` | 不知道／已知時辰／精確時間 |
| `br` | 時辰代碼 | `tm=br` 時必填 |
| `t` | `HH:mm` | `tm=ex` 時必填 |
| `dm` | `folk`／`civil` | 換日模式 |

規則：

- 新分享連結固定輸出 `v=1`、`bm` 及 `dm`。
- `bm=s` 時 `b` 必填，忽略 `ly`、`lm`、`ld`。
- `bm=l` 時 `ly`、`lm`、`ld` 必填，忽略 `b`。
- 分享 URL 只包含目前出生模式資料。
- `tm=br` 時 `br` 必填。
- `tm=ex` 時 `t` 必填。
- 直接農曆模式不包含閏月參數。

範例：

```text
?v=1&bm=s&g=m&b=1993-01-20&tm=ex&t=02%3A30&dm=folk
```

```text
?v=1&bm=l&g=m&ly=1992&lm=12&ld=8&tm=ex&t=02%3A30&dm=folk
```

### 13.3 相容策略

- 讀取時支援舊版長參數及新版短參數。
- 同一欄位的新舊參數同時存在時，新版短參數優先。
- 新版只輸出短參數。
- 舊連結沒有 `bm` 但有 `b` 或舊版生日參數時，視為國曆模式。
- 讀取缺少 `dm` 的舊連結時使用 `folk`。
- 保留舊格式解析能力，不再產生舊格式。

### 13.4 有效分享連結

- 完整驗證後自動還原表單並顯示結果。
- 顯示「此結果來自分享連結」。
- 保留 URL parameters，重新整理後仍可還原。
- 不自動保存或覆蓋本機資料與設定。
- 使用者修改會影響結果的資料並重新產生後，以 `history.replaceState` 清除舊分享參數。
- 展開詳細資訊、捲動或其他不改變計算結果的操作不清除 URL。
- URL 分享參數必須代表目前畫面結果；不一致時必須移除。

### 13.5 無效分享連結

- 保留原始 URL，不自動修改。
- 不載入個人資料或個人結果。
- 非個人的今日資訊正常顯示。
- 顯示：「分享連結無效或資料不完整，無法還原資料。」
- 提供「清除此分享連結」。
- 使用者主動清除後才移除 query parameters，並重新依 URL、LocalStorage、預設值的優先順序初始化。

### 13.6 分享確認

- 使用頁面內 Modal，不使用瀏覽器原生 `confirm()`。
- 標題：「建立分享連結」。
- 說明分享 URL 包含個人資料，任何取得連結者皆可還原。
- 操作：「取消」、「同意並複製連結」。
- 確認後才寫入剪貼簿。
- 成功顯示「分享連結已複製」。
- Clipboard API 失敗時提供手動複製文字框，需支援 LINE WebView。
- Modal 支援 Tab、Enter、Escape、focus trap 及關閉後焦點恢復。

「下次分享時不再提醒」：

- 只在「記住設定」已啟用時提供。
- 屬於本機 UI 偏好，不進入分享 URL。
- 關閉「記住設定」時立即移除，後續恢復提醒。
- 系統預設每次分享皆提醒。
